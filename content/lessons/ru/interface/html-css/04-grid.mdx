<DropCap>C</DropCap>SS Grid решает задачу, которую веб двадцать лет пытался обойти: одновременная раскладка по строкам и колонкам, где элементы удерживают позиции на обеих осях. Спецификация *CSS Grid Layout Module Level 1* (W3C) получила статус Candidate Recommendation в сентябре 2017; Chrome 57, Firefox 52 и Safari 10.1 выкатили реализацию ещё в марте 2017 на основе стабилизированного Working Draft, Edge подтянулся осенью — редкий случай в истории браузеров. До Grid двумерная вёрстка собиралась из float, position absolute и table — каждое со своим набором ограничений. Этот урок — про точное чтение grid-properties: что задаёт сетку, что распределяет пространство, что размещает детей.

<SectionBreak id="01" label="GRID НЕ ЕСТЬ FLEXBOX-С-WRAP" />

Первое, что мешает читать Grid тем, кто пришёл из Flexbox, — ощущение, будто `flex-wrap: wrap` уже даёт двумерную раскладку. На картинке — да. На уровне модели — нет: Flexbox с переносом создаёт N независимых линий, каждая распределяет пространство сама. Если в первой линии четыре карточки, а во второй — три, ширины колонок в этих линиях совпадать не обязаны. На одинаковых детях это не видно, но как только размеры расходятся, разница вылезает: правый край второй линии не совпадает с правым краем первой, колонки «гуляют».

Grid задаёт rows и columns заранее, до того как в него попадают дети. Все элементы ложатся в общую сетку — клетка во второй колонке первой строки находится ровно над клеткой во второй колонке второй строки, потому что обе принадлежат одной и той же вертикальной направляющей. Колонки и строки — общий координатный каркас, не локальное распределение.

Принципиальная разница формулируется одной парой слов. Flexbox — content-driven: распределение зависит от того, что внутри, и подстраивается под содержимое каждой линии отдельно. Grid — layout-driven: структура задана сеткой, content в неё ложится. В первом случае система реагирует на детей; во втором — навязывает им координаты.

Из этого следует разделение задач. Flex берёт одномерные раскладки: список, navbar, тулбар, поля формы, тэги — всё, что укладывается в одну ось с возможным переносом. Grid берёт двумерные: карточная сетка три-на-четыре, dashboard, holy grail layout с header / sidebar / main / aside / footer, формы с явным выравниванием label и input по двум вертикальным линиям. Эти задачи можно собрать и на Flex, но ценой ручного счёта ширины и хрупких хаков; Grid делает это декларативно.

Модели комбинируют: страница строится Grid'ом, регионы внутри — Flex'ом. Header — flex-row, main — внутренняя grid, footer — flex-row. Каждая модель решает то, в чём сильнее.

<SectionBreak id="02" label="GRID-TEMPLATE-COLUMNS / ROWS" />

Сердцевина Grid — два свойства: `grid-template-columns` и `grid-template-rows`. Они задают tracks — направляющие, между которыми лежат cells. Значения — список размеров, по одному на колонку (или строку).

```css
.dashboard {
  display: grid;
  grid-template-columns: 240px 1fr;
  grid-template-rows: 64px 1fr;
  gap: 24px;
}
```

Здесь две колонки: первая 240 пикселей фиксированно (под sidebar), вторая занимает всё оставшееся пространство. Две строки: верхняя 64 пикселя (под header), нижняя — оставшееся.

Размеры записываются в нескольких единицах, и каждая ведёт себя по-своему.

**Фиксированные** — `px`, `rem`, `em`. `200px` — двести пикселей, не больше и не меньше; не реагирует на размер контейнера. Подходит для зон гарантированной ширины: sidebar навигации, узкая колонка с метаданными, иконка в начале строки.

**Процентные** — `%`. Считаются от inline-size родителя. `50% 50%` дают две равные колонки, но не учитывают `gap`: на ширине 800 px с `gap: 20px` колонки остаются по 400 px, и сетка вылезает за пределы на 20 px. Процент в `grid-template-columns` поэтому неудобен; почти всегда лучше — `1fr`.

**`fr`** — fraction unit, доля свободного пространства. `1fr 2fr` означает «разделить остаток между двумя колонками в пропорции 1 к 2». «Остаток» — это ширина контейнера минус все фиксированные tracks и все gap'ы. На контейнере 800 px с `grid-template-columns: 200px 1fr 1fr` и `gap: 20px` остаток равен 800 − 200 − 20 − 20 = 560 px, разделённый поровну: вторая и третья колонки получают по 280 px каждая. Именно поэтому `1fr` нельзя приравнять к `33.33%` — `fr` арифметически вычитает фиксированные tracks и gap'ы, проценты этого не делают.

**`auto`** — размер по содержимому. Колонка занимает столько, сколько просит самый широкий ребёнок в ней. Полезно для строк типа icon + text + value, где первая и третья колонки — auto, средняя — `1fr`.

**`minmax(min, max)`** — диапазон. `minmax(200px, 1fr)` означает «не уже 200, не шире 1fr». Защищает от слишком узких колонок: на маленьком контейнере, где `1fr` сжался бы до 120 px, колонка остановится на 200 и пойдёт overflow вместо нечитаемого squeeze. Канонический контракт для responsive-grid'ов.

```css
.layout {
  display: grid;
  grid-template-columns: minmax(200px, 240px) minmax(0, 1fr) minmax(200px, 280px);
  gap: 24px;
}
```

Здесь sidebar колеблется между 200 и 240 px, основная колонка занимает остаток, правая колонка — между 200 и 280 px. `minmax(0, 1fr)` для main — частый идиом: без `min: 0` `1fr` имеет implicit minimum равный `min-content` колонки, и длинное слово или таблица распирают её, выталкивая соседей. `minmax(0, 1fr)` снимает это поведение и даёт колонке честно сжиматься до нуля.

**Implicit rows и columns.** Если детей больше, чем явных rows, Grid создаёт implicit rows — они появляются автоматически. Их размер задаётся `grid-auto-rows: 100px` (или любым другим значением). По умолчанию implicit rows имеют размер `auto` — высоту по содержимому. Та же логика для колонок: `grid-auto-columns` задаёт implicit columns. На практике implicit columns используются редко (структуру колонок обычно фиксируют явно), implicit rows — постоянно (на ленте карточек число строк зависит от количества записей).

Candidate Recommendation с февраля 2017, реализована в Chrome 57, Firefox 52, Safari 10.1 и Edge 16 практически синхронно. Эпизод считается одним из самых успешных в истории веб-стандартов: долгая проработка в W3C дала браузерам общий ориентир и одновременную выкладку.
</MarginNote>

<SectionBreak id="03" label="REPEAT, AUTO-FILL, AUTO-FIT" />

Когда колонок много или их число зависит от ширины экрана, явный список становится громоздким и плохо адаптируется. Спецификация даёт две функции, снимающие эту проблему: `repeat()` для повторения и пара ключевых слов `auto-fill` / `auto-fit` для динамического числа колонок.

`repeat(N, value)` повторяет значение N раз. `repeat(3, 1fr)` эквивалентно `1fr 1fr 1fr`; `repeat(12, 1fr)` задаёт 12-колоночную сетку одной строкой. Значение может быть любым: `repeat(4, minmax(200px, 1fr))`, `repeat(3, [col-start] 1fr [col-end])` с именованными линиями.

`repeat(auto-fill, minmax(200px, 1fr))` — другая семантика. Браузер сам считает, сколько колонок не уже 200 px поместится в контейнер, и создаёт ровно столько. На ширине 800 px и `gap: 20px` влезает три колонки (3 × 200 + 2 × 20 = 640) с запасом в 160 px, который делится между ними как `1fr` — финальные колонки по ~253 px каждая. На 1200 px влезает пять колонок по ~216 px. Никаких media queries: сетка перестраивается под ширину автоматически.

```css
.cards {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(280px, 1fr));
  gap: 24px;
}
```

`auto-fit` против `auto-fill` — разница появляется, когда детей меньше, чем влезающих по ширине колонок. Допустим, контейнер 1200 px, `minmax(280px, 1fr)`, gap 24 — влезает четыре колонки. В сетке три карточки.

**`auto-fill`** оставляет четвёртый track как пустой слот: три карточки занимают первые три колонки, четвёртая колонка пуста, ширина каждой — около 285 px. Сетка ведёт себя так, словно четвёртый ребёнок есть, но он невидим.

**`auto-fit`** коллапсирует пустые tracks: остаются три track'а, все вместе делят свободное пространство, каждый получает примерно 384 px. Карточки растягиваются на всю ширину контейнера.

Выбор зависит от семантики раскладки. Для карточной ленты, где визуальный приоритет — заполнить ширину, обычно `auto-fit`: пустые слоты выглядят странно, лучше пусть карточки шире. Для fixed-position grid'а, где колонки должны держать ширину независимо от количества элементов (например, календарь, где недели имеют по семь дней, и пустые ячейки — это пустые дни), `auto-fill`: четвёртый track обязан остаться, даже если в нём ничего нет.

`auto-fill` и `auto-fit` работают только с `minmax()`-значением: браузеру нужен min, от которого считать «сколько влезает», и max, до которого можно растянуть. `repeat(auto-fit, 200px)` без minmax не имеет смысла — track фиксирован, и автоматический подсчёт упирается в фиксированную ширину без возможности распределить остаток.

<SectionBreak id="04" label="GRID-AREAS" />

Grid даёт два способа размещать детей по сетке. Первый — координатами линий (`grid-column: 2 / 4`). Второй — именованными регионами (`grid-area: header`). Второй способ — одна из самых выразительных конструкций CSS: ASCII-схема макета прямо в стиле.

```css
.app {
  display: grid;
  grid-template-areas:
    "header header header"
    "sidebar main aside"
    "footer footer footer";
  grid-template-columns: 240px 1fr 200px;
  grid-template-rows: 64px 1fr 48px;
  gap: 16px;
  min-height: 100dvh;
}

.header  { grid-area: header; }
.sidebar { grid-area: sidebar; }
.main    { grid-area: main; }
.aside   { grid-area: aside; }
.footer  { grid-area: footer; }
```

`grid-template-areas` принимает строки в кавычках — каждая строка описывает одну row сетки, каждое слово в строке — клетку. Одно и то же имя в соседних клетках сливает их в один регион: `"header header header"` означает «вся первая row — это header». Точка `.` обозначает пустую клетку. Имена в `grid-template-areas` и в `grid-area` детей должны совпадать.

Holy grail layout — каноничный пример: header сверху на всю ширину, sidebar слева, main по центру, aside справа, footer снизу на всю ширину. До Grid он собирался либо на float'ах с `clearfix` и хрупкими `min-height`, либо на flex-обёртках в три уровня. С `grid-template-areas` — одна декларация, читаемая как картинка.

Reorder без перестановки HTML — практическое следствие. Source-order в HTML фиксирован (он определяет логический порядок чтения, табинг, screen reader), но визуальный порядок задаётся именами в `grid-template-areas`. Можно поменять местами sidebar и aside, переписав строки, без правки разметки. Это полезно и для accessibility: логический порядок остаётся стабильным, визуальный адаптируется.

Responsive-вариант пишется чисто. На mobile тот же layout превращается в одну колонку:

```css
@media (max-width: 768px) {
  .app {
    grid-template-areas:
      "header"
      "main"
      "sidebar"
      "aside"
      "footer";
    grid-template-columns: 1fr;
    grid-template-rows: 64px auto auto auto 48px;
  }
}
```

Дети не меняются — ни их HTML, ни их `grid-area`. Меняется только описание сетки. Логика «как выглядит макет» собрана в одном месте, в одном свойстве — это редкое качество в CSS.

<SectionBreak id="05" label="GRID-COLUMN / GRID-ROW SPAN" />

Поверх безымянной сетки и regions-схемы Grid даёт явное координатное позиционирование. Каждая клетка имеет адрес — пара line numbers по обеим осям. Линии нумеруются с 1 (левый/верхний край) и могут считаться с конца с −1 (правый/нижний край).

`grid-column: 1 / 3` означает «занять колонки от линии 1 до линии 3». Линии — это границы tracks; цифра указывает на линию, не на колонку. Колонка между линиями 1 и 3 — это две колонки (1-я и 2-я). Конечная линия exclusive: запись `1 / 3` берёт track между 1 и 2 и track между 2 и 3, на четвёртую линию не заходит.

`grid-column: span 2` — относительная запись: «занять две колонки от текущей позиции». Удобно, когда явная позиция определяется auto-placement'ом, а нужно только указать ширину. `grid-column: 2 / span 2` фиксирует начало (с линии 2) и длину (две колонки).

`grid-column: 1 / -1` — full-width трюк. `-1` — последняя линия в направлении движения. Запись означает «от первой линии до последней» — карточка занимает все колонки сетки независимо от их количества. Полезно для hero-блоков, заголовков секций, разделителей внутри grid-ленты.

```css
.feed {
  display: grid;
  grid-template-columns: repeat(4, 1fr);
  gap: 24px;
}

.feed > .featured {
  grid-column: 1 / -1;
}

.feed > .double {
  grid-column: span 2;
}
```

Те же правила для row: `grid-row: 1 / 3`, `grid-row: span 2`, `grid-row: 1 / -1`. Shorthand `grid-area: row-start / column-start / row-end / column-end` объединяет обе оси: `grid-area: 1 / 1 / 3 / 3` — клетка от первой линии до третьей по обеим осям, занимает 2×2.

Overlapping элементов — отдельный кейс. Два ребёнка, размещённых на одной grid-area, накладываются друг на друга — это легитимная конструкция. Hero с фоновой картинкой и текстом сверху собирается так: оба элемента указывают `grid-area: 1 / 1`, оба ложатся в одну клетку, разделяет их `z-index`. До Grid эта задача решалась `position: absolute` с явными координатами; в Grid она остаётся в потоке и адаптируется к размеру сетки.

<SectionBreak id="06" label="GAP, ALIGN, JUSTIFY" />

Между cells в Grid живёт `gap` — расстояние, заданное на родителе. В Grid `gap` работает с самого начала спецификации (2017); в Flexbox эту же функцию добавили только в 2021 (Safari 14.1, и все три браузера наконец совпали по поведению). До этого в Flex расстояние между детьми эмулировалось через `margin`, что требовало `:first-child` / `:last-child`-сбросов и плохо сочеталось с переносом.

`gap: 24px` задаёт одинаковый зазор по обеим осям. `gap: 16px 24px` — раздельно: 16 между rows, 24 между columns. Старые имена `grid-gap`, `grid-row-gap`, `grid-column-gap` существуют как aliases, но в новом коде используется унифицированное `gap` — оно работает и в Grid, и в Flexbox, и в multi-column.

Внутри клетки content выравнивается двумя свойствами:

- **`justify-items`** — выравнивание по inline-оси (горизонталь в LTR). Принимает `start`, `end`, `center`, `stretch`. По умолчанию — `stretch`: content растягивается на всю ширину клетки.
- **`align-items`** — выравнивание по block-оси (вертикаль). Те же значения, тот же default `stretch`.

Shorthand `place-items: center` ставит оба свойства в `center`. Идиоматичный one-liner для центрирования: `display: grid; place-items: center;` на родителе центрирует единственного ребёнка по обеим осям без подсчёта margin'ов.

Те же два слова в варианте `-content` работают на другом уровне:

- **`justify-content`** — выравнивание самой сетки внутри grid-container'а по inline-оси, если сетка уже container'а.
- **`align-content`** — то же по block-оси.

Разница принципиальна. `align-items` двигает content внутри каждой клетки. `align-content` двигает всю сетку как целое относительно container'а. Если `grid-template-rows: 100px 100px` суммарно задают 200 px, а container высотой 400 px, то 200 px свободны: `align-content: start` прижмёт сетку к верху, `center` — поставит по центру, `space-between` — растащит две rows к верху и низу. Для Flexbox-разработчиков это место часто становится точкой путаницы: в Flex `align-content` работает, только когда есть `wrap`; в Grid — всегда, потому что rows известны до распределения.

```css
.modal {
  display: grid;
  place-items: center;
  min-height: 100dvh;
}

.modal > .panel {
  display: grid;
  grid-template-columns: 1fr;
  gap: 16px;
  padding: 32px;
  max-width: 480px;
}
```

Внешний grid центрирует panel; внутренний — раскладывает содержимое panel в одну колонку с зазором 16. Без подсчёта высоты, без `position: absolute`, без translate-хаков.

Парная статья «A Complete Guide to Flexbox» — такой же канон по Flex; вместе они закрывают 90% рутинных задач, не требуя обращения к спецификации.

Выбор между Grid и Flex сводится к одному вопросу: задача одномерна или двумерна. Список, в котором элементы выстроены вдоль одной оси (с переносом или без), — Flex. Сетка, в которой элементы должны выровняться сразу по двум осям и держать колонки между rows, — Grid. Раскладка целой страницы — почти всегда Grid; раскладка регионов внутри — часто Flex.

Второй критерий — что задаёт структуру: содержимое или layout. Если ширина колонок зависит от того, что в них (тэги переменной длины, navbar с разными лейблами), — Flex. Если ширина колонок задана дизайном и content должен в неё вписаться (карточная сетка, holy grail, форма с aligned label/input), — Grid. Андру в *The New CSS Layout* формулирует это как «Flex shrinks to content, Grid imposes layout».

Третий — gap и alignment. Обе модели используют `gap` одинаково, обе принимают `place-items` / `place-content`. Это не различитель — это общая часть, которую стоит знать, чтобы переключаться между моделями без перенастройки головы.

Связь с уроком `foundations/composition/02-grids-deep` — прямая. Там сетка обсуждается на уровне дизайна: 16 колонок против 12, outer margin, breakpoints как контракт, subgrid и container queries как современные расширения. Здесь — на уровне CSS: как грид-токены превращаются в исполняемый код. Subgrid (`grid-template-rows: subgrid`) — это уже Grid Level 2, и он закрывает класс задач, для которых Grid Level 1 требовал ручной разводки строк на родителе. Container queries — отдельная спецификация (CSS Containment Module Level 3), но они почти всегда живут поверх Grid: компонент знает, в какую сетку он встал, и реагирует на её размер.

Дальше в треке — `05-container-queries`: единицы `cqw` / `cqi`, `@container`-правило, переход компонента из «знает viewport» в «знает свой контейнер». После этого блока инструменты двумерной раскладки замкнут полный круг: box model задаёт коробку, Flex распределяет её по одной оси, Grid — по двум, container queries дают коробке знание о собственном контексте. Каждый следующий слой работает поверх предыдущих — не вместо них.
