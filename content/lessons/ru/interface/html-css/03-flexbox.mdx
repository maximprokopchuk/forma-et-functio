<DropCap>F</DropCap>lexbox решает одну задачу: распределить N элементов вдоль одной оси с заданными правилами выравнивания и распределения свободного пространства. Двумерная раскладка — задача Grid; реакция на размер контейнера — container queries; геометрия одного элемента — box model. Flexbox живёт между этими слоями и описывает поведение группы по одной оси: navbar, список действий, header с logo и nav, форма с label и input. Этот урок — про точную семантику flex-properties и про границу, где Flexbox заканчивается и начинается Grid.

<SectionBreak id="01" label="ОДНА ОСЬ" />

Спецификация *CSS Flexible Box Layout Module Level 1* (W3C, Candidate Recommendation с октября 2017, последняя редакция 2018) описывает Flexbox как одномерную layout-модель. «Одномерная» здесь — не оговорка: контейнер распределяет детей вдоль одной выбранной оси, а перпендикулярная ось работает только для выравнивания, не для распределения. Это принципиальное отличие от Grid, который держит обе оси как равноправные.

Контейнер задаётся `display: flex` (или `display: inline-flex`, если сам контейнер должен оставаться inline). Дети становятся flex-items: блочный флоу внутри отменяется, margin-collapse не работает, float игнорируется, дети встают вдоль main axis.

**Main axis** — ось распределения. **Cross axis** — перпендикулярная, для выравнивания. Какая из них главная, определяет `flex-direction`:

- `row` (default) — main горизонтальна, направление от start к end совпадает с inline-направлением документа. На LTR это слева направо, на RTL — справа налево.
- `column` — main вертикальна, сверху вниз.
- `row-reverse`, `column-reverse` — те же оси с обратным направлением.

Переключая `flex-direction`, дизайнер не «крутит контейнер на 90 градусов», а меняет, какая ось считается главной. Все остальные flex-свойства зависят от этого выбора: `justify-content: flex-end` в `row` прижимает детей вправо, в `column` — вниз; `align-items: center` в `row` центрирует по вертикали, в `column` — по горизонтали. Запутанность — следствие того, что свойства привязаны к main/cross, а не к экрану.

Когда выбирать Flexbox: navbar в строку, вертикальный список с равными gap, header `logo / nav / cta`, форма-строка с label и input, теги с переносом. Когда выбирать Grid: сетка карточек 3×4, holy grail layout, dashboard, форма с двумя и более вертикальными направляющими. Правило короткое: если в макете есть структура по обеим осям одновременно — Grid; если только по одной — Flex. Rachel Andrew в *The New CSS Layout* (A Book Apart, 2017) формулирует то же иначе: Flexbox раздаёт пространство, Grid раскладывает по координатам.

<MarginNote>
*CSS Flexible Box Layout Module Level 1* (W3C, drafts.csswg.org/css-flexbox) — нормативная спецификация Flexbox. Candidate recommendation с октября 2017, последняя редакция 2018. Уровень 1 формализует main/cross-терминологию и flex-алгоритм; Level 2 в раннем драфте.
</MarginNote>

<SectionBreak id="02" label="JUSTIFY ПРОТИВ ALIGN" />

Два мира flex-выравнивания работают по разным осям, и путаница между ними — самый частый источник «не понимаю, почему не центрируется».

**`justify-content`** распределяет детей по **main axis**. Значения: `flex-start` (default — все слева в `row`), `flex-end` (справа), `center`, `space-between` (равные промежутки между, без отступов по краям), `space-around` (равные промежутки вокруг каждого элемента — на краях половинный), `space-evenly` (одинаковые промежутки между и по краям).

**`align-items`** выравнивает детей по **cross axis**, по умолчанию для всех. Значения: `stretch` (default — растягивает детей на всю высоту контейнера в `row`), `flex-start`, `flex-end`, `center`, `baseline` (выравнивание по типографической baseline текста — критично для строк с разными кеглями).

**`align-self`** переопределяет `align-items` для одного ребёнка. Если в navbar пять ссылок центрированы по вертикали, а аватар справа должен быть прижат к низу — на нём `align-self: flex-end`.

**`align-content`** работает только в multi-line wrap-контейнере (об этом в секции 05). Распределяет ряды детей по cross axis — не по одному ребёнку, а целые строки.

```css
.toolbar {
  display: flex;
  justify-content: space-between;
  align-items: center;
  gap: 12px;
  padding-block: 8px;
  padding-inline: 16px;
}

.toolbar__title {
  align-self: baseline;
}
```

Названия зависят от `flex-direction`. В `row` `justify-content: center` — горизонтальное центрирование, `align-items: center` — вертикальное; в `column` ровно наоборот. Конвенция, которую держать в голове: justify работает вдоль main, align — поперёк. Не «по горизонтали», а вдоль выбранной main axis.

`place-content: center` — shorthand, центрирующий сразу по обеим осям, валидный и в Flexbox, и в Grid. Внутри Flexbox `justify-items` не существует (распределение по main делает `justify-content`), но `place-*` форма часто читается короче двух раздельных свойств.

<SectionBreak id="03" label="FLEX-GROW / SHRINK / BASIS" />

Эти три свойства — центральные и наиболее нелогичные в Flexbox. Их совместная работа описывает арифметику свободного пространства: сколько у контейнера лишних или недостающих пикселей и как они распределяются между детьми.

**`flex-basis`** — желаемый размер ребёнка по main axis до распределения. Аналог `width` для `row` или `height` для `column`. Default — `auto`: размер по содержимому. Может быть числом (`flex-basis: 200px`), процентом (`flex-basis: 50%`), `0` (игнорировать содержимое, считать с нуля), ключевыми словами `min-content` / `max-content` / `fit-content`.

**`flex-grow`** — коэффициент растяжения, если у контейнера остаётся свободное место. Default `0`: не расти. `flex-grow: 1` всем детям — поделить free space поровну. `flex-grow: 2` одному ребёнку при `flex-grow: 1` у остальных — тот получает вдвое больше остального free space. Здесь критично: распределяется не общая ширина, а только остаток после basis.

**`flex-shrink`** — коэффициент сжатия, если детям не хватает места. Default `1`: сжимаются пропорционально. `flex-shrink: 0` — не сжимать ни при каких условиях. Типичный случай — иконки фиксированного размера: `flex-shrink: 0` гарантирует, что иконка останется 24×24 даже когда соседний текст вытесняет её.

**`flex` shorthand** — три свойства одной строкой. Самое частое значение — `flex: 1`, и оно нелогично разворачивается в `flex: 1 1 0%`. То есть: расти с коэффициентом 1, сжиматься с коэффициентом 1, basis — 0%. Из-за `basis: 0%` распределение игнорирует размер содержимого: два элемента с `flex: 1` получают по 50% main-оси, элементы с `flex: 1` и `flex: 2` — треть и две трети. Это «равные доли», а не «равные ширины»: разница станет важной в секции про ошибки.

Альтернативные shorthand-ы: `flex: auto` = `1 1 auto` (расти от content, сжиматься), `flex: none` = `0 0 auto` (фиксированный размер по content, не растёт и не сжимается), `flex: 0 1 auto` — спецификационный default (не растёт, сжимается, размер по content).

```css
.list {
  display: flex;
  gap: 16px;
  align-items: center;
}

.list__icon {
  flex: 0 0 24px;
}

.list__label {
  flex: 1 1 0;
  min-width: 0;
}

.list__cta {
  flex: 0 0 auto;
}
```

В этом примере иконка зафиксирована на 24 пикселя, label занимает всё свободное место и при необходимости отдаст его соседям, кнопка остаётся ровно той ширины, которую требует содержимое. Каждый из трёх детей описывает разный режим: рассказать всё через одно свойство shorthand-ом — типичная мотивация существования `flex`.

<SectionBreak id="04" label="GAP И MARGIN-AUTO" />

До 2021 года `gap` в Flexbox не работал, и расстояние между детьми задавали через margin с селектором-сиблингом — конструкция плохо переносилась на wrap-контейнеры, давая лишний отступ на новой строке.

`gap` пришёл в Flexbox с Firefox 63 (октябрь 2018), Chrome 84 (июль 2020) и Safari 14.1 (апрель 2021). С весны 2021 это безопасный baseline. Свойство задаёт расстояние между соседями (column-gap) и между строками в wrap (row-gap); `gap: 16px` — оба одинаковы, `gap: 16px 24px` — row-gap 16, column-gap 24.

```css
.nav {
  display: flex;
  gap: 24px;
  align-items: center;
}

.nav__login {
  margin-inline-start: auto;
}
```

`margin: auto` на flex-item — старый трюк, удобный в одном сценарии: один элемент уходит к концу оси, остальные остаются в начале. В навигации с ссылками и кнопкой логина `margin-inline-start: auto` на кнопке прыгает её в самый конец, остальное остаётся слева. Альтернатива через `justify-content: space-between` с пустым spacer длиннее и читается хуже.

`margin: auto` работает по обеим осям. `margin-block: auto` на одном ребёнке центрирует его по cross axis, остальные сохраняют `align-items` — редкий способ переопределить выравнивание без `align-self`.

Главное преимущество `gap` над margin — отсутствие коллизий. Margin на детях требует сброса `:first-child` или `:last-child`, иначе зазор появится у края. С `gap` зазор существует только между соседями, по краям — никогда; на wrap-контейнере gap нативно работает через `row-gap`.

<SectionBreak id="05" label="FLEX-WRAP" />

`flex-wrap: nowrap` (default) запирает детей в одну линию: при переполнении они либо сжимаются (если `flex-shrink > 0`), либо выходят за пределы контейнера. Это поведение «одной строки», на котором держится одномерная природа Flexbox.

`flex-wrap: wrap` разрешает переход на новую строку, когда не хватает места. Контейнер становится семи-двумерным: дети распределяются по нескольким рядам, и в дело вступают `align-content` (распределение рядов по cross axis) и `row-gap` (расстояние между рядами).

```css
.tags {
  display: flex;
  flex-wrap: wrap;
  gap: 8px;
}

.tag {
  flex: 0 0 auto;
  padding-inline: 12px;
  padding-block: 4px;
  border-radius: 999px;
  background: var(--surface-2);
}
```

Облако тегов — каноническая задача для wrap. Каждый тег фиксирован по содержимому (`flex: 0 0 auto`), теги переносятся, gap работает по обеим осям. Здесь Flexbox остаётся естественным выбором: длина каждого тега произвольна, выравнивание по сетке не нужно.

Граница с Grid проходит по природе задачи. Если макет требует wrap с равными колонками одинаковой ширины — это уже сетка, и решение через Flexbox с `flex: 1 1 200px` плюс `flex-wrap: wrap` справится, но даст неровный последний ряд (последняя строка с двумя элементами растянется на всю ширину). Grid с `repeat(auto-fit, minmax(200px, 1fr))` решает ту же задачу с одной колонкой кода и одинаковыми треками. Heuristic: если в wrap-контейнере все дети визуально одинакового размера и образуют сетку — переходить на Grid; если они разной ширины и заполняют ряд по содержимому, как теги или фильтры — оставлять Flexbox.

`align-content` в wrap-режиме принимает те же значения, что `justify-content`: `flex-start`, `center`, `space-between`, `space-around`, `space-evenly`, `stretch`. Без wrap эти значения игнорируются. Это часть путаницы между `align-items` (выравнивание детей в одной строке) и `align-content` (распределение строк): первое работает всегда, второе — только в multi-line.

<SectionBreak id="06" label="ЧАСТЫЕ ОШИБКИ" />

Несколько ошибок встречаются в каждом проекте, который использует Flexbox без полного понимания арифметики. Каждая стоит проверки в коде ревью.

**`flex: 1` без понимания basis.** «Равные доли» не равны «равным ширинам». Если у одного ребёнка длинный неразрывный текст или большое изображение, его intrinsic-размер вмешается в распределение. Решений два: `flex: 1 1 0` явно — basis нулевой, доли честно равны; или `min-width: 0` на всех детях, чтобы content мог быть сжат до меньшего размера. По умолчанию `min-width: auto` у flex-items равен intrinsic content size — это блокирует сжатие. `min-width: 0` снимает блокировку, и `text-overflow: ellipsis` начинает работать.

**`align-items: center` ожидает горизонтальное центрирование.** В `flex-direction: row` (default) это вертикальное центрирование. Для горизонтального — `justify-content: center`. На `flex-direction: column` всё переворачивается. Запомнить: align — поперёк, justify — вдоль.

**Использование Flex как Grid.** Шесть карточек в три колонки через `flex-wrap: wrap` плюс `flex: 1 1 calc((100% - 32px) / 3)` — рабочий, но громоздкий код. Grid с `grid-template-columns: repeat(3, 1fr); gap: 16px` короче, надёжнее, не требует ручной арифметики gap внутри `calc`. Признак перегруза Flexbox: в коде появляется `calc()` от gap или ширины контейнера — это сигнал, что задача двумерная.

**Забытый `min-width: 0` на детях.** Текст с `text-overflow: ellipsis` или `overflow: hidden` не работает по умолчанию: default `min-width: auto` не позволяет ребёнку быть уже своего intrinsic content size. Длинный URL или email в карточке толкает контейнер за пределы экрана. `min-width: 0` на flex-children, у которых ожидается обрезка текста, снимает проблему. Это документированное поведение в спецификации, но для большинства разработчиков выглядит как неожиданность.

**`flex-basis: 0` против `flex-basis: 0%`.** Оба валидны, но `0` без unit интерпретируется как длина в `px`, и в некоторых старых браузерах это давало edge-case с distribution-алгоритмом. Рекомендация из MDN — использовать `0%` или `0` с явным `flex` shorthand-ом. На современных движках разницы нет, но в старом коде встречается обе записи.

**`align-items` как селектор для одного ребёнка.** `align-items` — свойство контейнера, действует на всех детей сразу. Чтобы переопределить для одного — `align-self` на этом ребёнке. Частая ошибка: `align-items: flex-end` на ребёнке, в надежде, что только он опустится вниз — свойство в этом контексте игнорируется.

**Margin-collapse внутри flex.** Внутри flex-контейнера margin между детьми не схлопывается. Если из не-flex-кода скопирован пара параграфов с `margin-block`, в flex-контейнере зазоры удваиваются. Это документировано в спецификации как намеренное поведение: gap и margin в flex складываются, не пересекаются.

<SectionBreak id="07" label="СИНТЕЗ" />

Flexbox — модель распределения свободного пространства вдоль одной оси. Три практических правила:

- **Сначала ось, потом свойства.** Перед написанием flex-кода зафиксировать main axis: `row` или `column`. Все остальные свойства (justify, align, grow, shrink) читаются относительно этого выбора. Запутанность Flexbox почти всегда сводится к тому, что ось выбрана не та, которую держал в голове разработчик.
- **`flex: 1` означает `flex: 1 1 0`.** «Поделить пространство поровну» работает только при понимании, что `basis: 0` игнорирует content. Когда нужны равные доли с учётом content — `flex: 1 1 auto` или явный basis. Когда нужны равные ширины при разном content — `min-width: 0` на детях.
- **`gap` вместо margin.** В новом коде расстояние между детьми задаётся `gap` контейнера, не margin'ом детей. Это убирает коллизии с границами, упрощает переход в wrap-режим, не зависит от порядка детей. Margin остаётся для одного сценария — `margin: auto` как альтернатива `space-between`.

Граница Flexbox/Grid проходит по числу осей, а не по сложности. Простые двумерные задачи (карточки в сетку) решаются Grid даже когда «можно через flex»; одномерные задачи с разной шириной детей (теги, фильтры, navbar) остаются за Flexbox даже когда «можно через grid». Выбор по природе задачи, не по привычке.

Следующая тема трека — `04-grid`. Если Flexbox распределяет пространство по одной оси, Grid размещает элементы в координатной системе по двум: tracks, lines, areas, `repeat(auto-fit, minmax(...))`, subgrid. Box model из урока 02 остаётся фундаментом: и Flexbox, и Grid распределяют коробки, чьи габариты определены `box-sizing` и logical properties. Дальше, после Grid, идут container queries (`05-container-queries`), которые дают возможность реагировать на размер контейнера, а не viewport — и flex-распределение внутри начинает реагировать на собственного родителя.
