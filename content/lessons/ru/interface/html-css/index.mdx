<DropCap>Д</DropCap>изайнер интерфейса не обязан писать production-код, но обязан понимать материал, на котором интерфейс собирается. HTML и CSS — это бумага и краска веба: у них есть собственные свойства, ограничения и сильные стороны, которые проявляются независимо от того, замечает их автор макета или нет. Печатник, не знакомый со свойствами бумаги, выпускает книгу, в которой текст просвечивает с обратной стороны; дизайнер, не знакомый со свойствами разметки, выпускает интерфейс, который ломается на узком экране, не работает с клавиатуры и невидим для поисковика. Этот раздел проходит пять опор, на которых стоит современный фронтенд: семантическая разметка, box model как геометрия элемента, Flexbox как одномерная компоновка, Grid как двумерная сетка, container queries и logical properties как инструменты адаптации к контексту и языку. Цель — не научить кодить, а научить читать код и понимать, какие дизайн-решения он позволяет, а какие — отвергает. Без этой грамотности диалог дизайнера с разработчиком превращается в обмен предположениями; с ней — в общий технический разговор о компромиссах.
