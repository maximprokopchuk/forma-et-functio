<DropCap>К</DropCap>аждый HTML-элемент — это коробка из четырёх вложенных слоёв: содержимое, внутренний отступ, рамка, внешний отступ. Любая раскладка, от карточки в три строки до полнополосного редакционного макета, складывается из того, как эти слои считаются по ширине, как ведут себя при соседстве и какой у них режим вычисления. Box model — арифметика, на которой стоит весь CSS-layout: до Flexbox и Grid здесь решается, сколько места занимает элемент и почему. Эта тема — про геометрию коробки и про несколько правил, которые в спецификации записаны по историческим причинам и которые сегодня ломают интуицию чаще, чем помогают.

<SectionBreak id="01" label="ЧЕТЫРЕ СЛОЯ" />

Спецификация *CSS Box Model Module Level 3* (W3C) описывает каждый элемент как прямоугольник, окружённый тремя дополнительными прямоугольниками. Считая изнутри: content, padding, border, margin. Каждый слой имеет собственную семантику, собственное поведение по фону и собственные правила взаимодействия с соседями.

**Content** — внутренний прямоугольник, в котором живёт содержимое: текст, изображение, дочерние элементы. Его размер задаётся `width` и `height` (для горизонтальной письменности) или вычисляется браузером из intrinsic-размера содержимого. На картинке без явной `width` content-box равен пиксельным размерам файла; на параграфе — длине строки и количеству строк.

**Padding** — внутренний отступ между content и border. Принимает `background-color` и `background-image` элемента: фон карточки заливает и content, и padding одновременно. Padding не схлопывается, не отрицательный, всегда занимает место. Записывается через `padding-top`, `padding-right`, `padding-bottom`, `padding-left` или сокращённо: `padding: 16px 24px` — 16 сверху и снизу, 24 по бокам.

**Border** — рамка между padding и margin. Имеет толщину, стиль и цвет: `border: 1px solid #e5e5e5`. Стилей около десятка, но в продакшене живут три — `solid`, `dashed`, `dotted`. Толщина не нулевая занимает место и в одних режимах входит во внешний размер элемента, а в других нет — узкое место темы, к которому вернёмся в следующей секции.

**Margin** — внешний отступ от соседей. В отличие от padding, margin прозрачен и фон элемента не принимает: между двумя карточками с margin — пустота родителя. Margin может быть отрицательным: `margin-top: -1px` сшивает два border'а в один. Вертикальные margin схлопываются, горизонтальные — никогда.

Каждый слой имеет четыре стороны и принимает четыре значения: `padding: top right bottom left`. Аббревиатура расшифровывается по часовой стрелке от верха. Сокращения: одно значение — все четыре стороны; два — vertical / horizontal; три — top / horizontal / bottom. Эти правила одинаковы для `padding`, `margin`, `border-width`, `border-style`, `border-color`.

<MarginNote>
*CSS Box Model Module Level 3* (W3C, drafts.csswg.org/css-box-3) — нормативная спецификация box model'а для современного веба. Уровень 3 формализует то, что было размыто в CSS 2.1, и закрепляет терминологию: content edge, padding edge, border edge, margin edge.
</MarginNote>

<SectionBreak id="02" label="BOX-SIZING" />

Самый последствий ноль-один-выбор в layout — `box-sizing`. Свойство принимает два значения, и от выбора зависит, что считается «шириной» элемента.

**`content-box`** — спецификационный default. `width` задаёт размер content-box, padding и border добавляются сверху. Кнопка с `width: 100px; padding: 10px; border: 2px solid` занимает по горизонтали 100 + 10·2 + 2·2 = 124 пикселя. Размер content под `width` равен заявленной величине; внешний габарит — больше.

**`border-box`** — что используют все. `width` задаёт размер border-box, и padding с border вычитаются изнутри. Та же кнопка занимает ровно 100 пикселей; content-box внутри неё — 76. Размер, на который ссылается grid или flex-распределение, совпадает с числом в CSS — без арифметики.

```css
*,
*::before,
*::after {
  box-sizing: border-box;
}
```

Эта строка — самый узнаваемый сниппет CSS-reset'а. Paul Irish в феврале 2012 года сформулировал её в посте «Box-sizing: border-box FTW» как «единственную полезную одну строку CSS», и за два года она стала индустриальным дефолтом. Bootstrap 3 (август 2013) включал её в base; Tailwind держит в preflight с первой версии; modern CSS reset Andy Bell открывается ровно этой формулой. Normalize.css сознательно её не добавляет, оставляя box-sizing на усмотрение проекта — это его принципиальное отличие от reset-стилей.

Причина устойчивости — выравнивание ментальной модели и кода. Дизайнер в Figma задаёт элементу ширину 320; разработчик пишет `width: 320px`. В content-box заявленное число расходится с фактическим габаритом: меняется padding — съезжает раскладка соседей. С border-box внутренние слои перераспределяются за счёт content, и заявленная ширина соблюдается.

Селектор с двумя псевдоэлементами нужен, потому что `::before` и `::after` не наследуют `box-sizing` через универсальный `*`. Без них псевдоэлементы остаются в content-box, и пиктограммы через `::before` ломают раскладку — деталь, которую Chris Coyier зафиксировал в CSS-Tricks в 2014 как уточнение к формуле Irish. Возвращаться к `content-box` имеет смысл только в работе со старым кодом, где раскладка построена на старой арифметике; смешивать оба режима в одном проекте — гарантированный источник багов.

<SectionBreak id="03" label="MARGIN COLLAPSE" />

Вертикальные margin двух соседних блоков схлопываются в наибольший. Параграф с `margin-bottom: 20px` рядом с параграфом с `margin-top: 30px` даёт 30 пикселей зазора, не 50. Это правило существует с CSS 1 (1996) и сегодня — одно из самых нелогичных мест языка для тех, кто пришёл из других layout-моделей.

Логика правила — типографическая. Вертикальный ритм абзацев в книжной вёрстке задаётся одним промежутком, не суммой. Если каждый автор расставляет margin на свой вкус и они складываются, между параграфами накапливаются разные зазоры — ритм ломается. Схлопывание гарантирует, что между двумя смежными блоками всегда стоит максимальный из заявленных margin'ов, а не их сумма.

Правила схлопывания:

- **Только вертикальные margin** (top и bottom). Горизонтальные не схлопываются никогда.
- **Только смежные.** Если между двумя элементами есть padding, border, content или элемент-разделитель — схлопывания нет.
- **Не работает в Flexbox и Grid.** Внутри flex- или grid-контейнера margin между детьми не схлопывается.
- **Положительные складываются по максимуму, отрицательные — по минимуму, разнознаковые — суммируются** (`+30px` и `−10px` дают `+20px`).
- **Margin родителя и первого/последнего ребёнка схлопываются**, если у родителя нет padding/border сверху/снизу. Margin первого `<p>` внутри `<section>` без padding «вылетает» наружу к margin самой `<section>` — частый источник «откуда взялся отступ».
- **Не схлопываются** margin вокруг плавающих (`float`) и абсолютно позиционированных элементов.

```css
/* Между двумя соседними параграфами — 30px, не 50 */
p { margin-block: 20px; }
p + p { margin-block-start: 30px; }

/* В flex-контейнере margin между детьми не схлопывается */
.stack {
  display: flex;
  flex-direction: column;
}
.stack > * + * { margin-block-start: 30px; }
```

Современный подход обходит схлопывание целиком. Вместо margin между блоками используется `gap` в Flexbox/Grid: `display: flex; flex-direction: column; gap: 24px` — между детьми ровно 24 пикселя, без правил схлопывания, без `:first-child` / `:last-child`-сбросов. Heydon Pickering и Andy Bell в шаблоне «The Stack» (Every Layout, 2019) вывели этот паттерн как стандартный приём вертикального ритма: контейнер задаёт расстояние, дети отступов не имеют. Правило схлопывания не отменили — это сломало бы миллионы существующих сайтов, — но сделали ненужным в новых layout-моделях.

<SectionBreak id="04" label="LOGICAL PROPERTIES" />

Старая физическая модель CSS привязана к экрану: `margin-top`, `padding-left`, `border-right`. Top — это всегда верх viewport'а, left — всегда левая сторона. Пока интерфейс работает только в LTR-горизонтальной письменности, всё совпадает. На арабском (RTL) интерфейс переворачивается, и `padding-left` оказывается «padding со стороны конца строки» — а нужно было «со стороны начала».

Logical properties описывают отступы относительно направления письма, не экрана. Спецификация *CSS Logical Properties and Values Level 1* (W3C, в драфтах с 2018, candidate recommendation в 2021) вводит две оси:

- **inline** — направление строки. На LTR — слева направо; на RTL — справа налево; в вертикальной письменности (японский tategaki) — сверху вниз.
- **block** — направление, перпендикулярное inline. Накопление абзацев: на горизонтальном тексте — сверху вниз; на вертикальном — справа налево.

Старое название → новое:

- `margin-top` → `margin-block-start`
- `margin-bottom` → `margin-block-end`
- `margin-left` → `margin-inline-start`
- `margin-right` → `margin-inline-end`
- `padding-top` → `padding-block-start` (и так далее)
- `border-top-width` → `border-block-start-width`
- `width` → `inline-size`
- `height` → `block-size`

Сокращения: `padding-block: 1rem` задаёт block-start и block-end одновременно, `padding-inline: 1.5rem` — оба inline-края. Для разных значений — `padding-block: 1rem 2rem` (start, end).

```css
.card {
  padding-block: 1rem;
  padding-inline: 1.5rem;
  margin-block-end: 2rem;
  border-inline-start: 4px solid var(--accent);
}
```

Поддержка стабильна с весны 2021 — Safari 14.1, Firefox 66, Chrome 87. К 2025 году logical properties — не альтернатива, а дефолт: пишут в физических только под legacy и третьесторонние стили. Tailwind с версии 3.3 (март 2023) даёт `ms-4` для `margin-inline-start`, `me-4` для end, `ps-4` / `pe-4` для padding.

Практический выигрыш виден в RTL-локализации. На LTR sidebar с `margin-left: auto` прижимается к правому краю; на RTL должен — к левому. С `margin-inline-start: auto` поведение одинаково в обоих направлениях: «прижать к концу inline-оси». Один CSS работает в арабском, английском и вертикальном японском, без отдельных стилей и без PostCSS-плагина для зеркалирования.

<MarginNote>
*CSS Logical Properties and Values Level 1* (W3C, drafts.csswg.org/css-logical) — спецификация уровня 1, в candidate recommendation с 2021 года. Заменяет физические свойства на пары осей block/inline и упрощает поддержку RTL и vertical writing modes.
</MarginNote>

<SectionBreak id="05" label="ЧТО ОЗНАЧАЮТ WIDTH И HEIGHT" />

Свойства `width` и `height` принимают разные классы значений, и значения эти ведут себя неодинаково. Деление по двум осям: extrinsic vs intrinsic, и фиксированное vs ограничивающее.

**Extrinsic** — размер задан явно числом. `width: 320px`, `width: 50%`, `width: 100vw`. Браузер не смотрит на содержимое: занимает ровно столько, сколько сказано. Процент считается от inline-size родителя; vw — от ширины viewport'а.

**Intrinsic** — размер вычисляется из содержимого. Три ключевых слова из *CSS Sizing Module Level 3* (W3C):

- `width: max-content` — ширина по самому широкому неразрывному фрагменту, без переноса. Параграф «Hello world» получает ширину 90 пикселей в шрифте кегля 16, без разрывов.
- `width: min-content` — ширина по самому узкому неразрывному фрагменту. Параграф «Hello world» получает ширину одного слова — самого длинного из двух.
- `width: fit-content` — между min и max. Принимает столько места, сколько нужно содержимому, но не больше доступного. Эквивалент старого хака `display: table` для shrink-to-fit.

```css
.tag {
  width: fit-content;
  padding-inline: 0.75rem;
  padding-block: 0.25rem;
  background: var(--surface-2);
}
```

**Min/max** — ограничители. `min-width` задаёт нижнюю границу: элемент не уже этого. `max-width` задаёт верхнюю: не шире. Канонический паттерн читаемой колонки:

```css
article {
  width: 100%;
  max-width: 65ch;
  margin-inline: auto;
}
```

Ширина — 100% контейнера, но не больше 65 символов на строку (баунд оптимальной длины из *Elements of Typographic Style* Брингхёрста). На узком экране — fluid; на широком — фиксированный. `ch` — единица размера символа «0» текущего шрифта; 65ch держит читаемость без подсчёта пикселей.

**`aspect-ratio`** — свойство, стабильное во всех major-браузерах с весны 2022 (последним закрыл baseline Safari 15.4). Задаёт соотношение сторон, второе измерение вычисляется браузером:

```css
.video {
  width: 100%;
  aspect-ratio: 16 / 9;
}

.avatar {
  width: 48px;
  aspect-ratio: 1;
  border-radius: 50%;
}
```

До `aspect-ratio` 16:9-видеоконтейнер делали через `padding-top: 56.25%`-хак: процентный padding считается от ширины родителя, и `56.25% = 9/16` даёт нужную пропорцию. Хак работал, но требовал absolute-позиционирования внутри и не масштабировался на произвольные пропорции. Нативное `aspect-ratio` снимает класс задач целиком.

**`height: 100%` без явной height у родителя — игнорируется.** Канонический пример: `<body>` без `height: 100vh`, внутри `<div style="height: 100%">` — div занимает по content. Браузер не может вычислить «100% от чего», если у родителя height не задана. Решения: `height: 100vh` на самом элементе; `display: flex` на родителе с `flex: 1` на ребёнке; `min-height: 100dvh` на body (с 2023 года `dvh` корректно учитывает мобильные toolbar'ы).

<SectionBreak id="06" label="ЧАСТЫЕ ОШИБКИ" />

Несколько ошибок в применении box model встречаются достаточно часто, чтобы быть отдельной темой.

**Margin против padding.** Margin — расстояние до соседей, снаружи; padding — внутренний отступ под фоном. Между заголовком и текстом карточки стоит padding (внутри, фон заливает зазор). Между карточкой и соседней — margin или, лучше, gap родительского контейнера. Путаница даёт либо текст, прилеплённый к рамке (нет padding), либо зазор, окрашенный в цвет карточки (margin сделан фоном).

**Border ломает width в content-box.** Кнопка `width: 100px; padding: 12px 24px; border: 2px solid` в content-box занимает 100 + 24·2 + 2·2 = 152 пикселя. Дизайнер задаёт 100, разработчик пишет `width: 100px`, кнопка съезжает на 52 пикселя. С `box-sizing: border-box` арифметики нет — заявленная ширина соблюдается. Это вторая причина (после mental model), почему border-box стал стандартом.

**`height: 100%` без явной height у родителя — игнорируется.** Современная замена — `100dvh` на полноэкранных layout'ах, flex/grid с `flex: 1` или `grid-template-rows: 1fr` для растягивания внутри родителя, container queries для адаптации без явных размеров.

**Padding в процентах считается от ширины, не от высоты.** `padding-top: 50%` на элементе шириной 600 пикселей — 300 пикселей сверху, не половина высоты. Спецификационный выбор: вертикальный процент тоже привязан к inline-size родителя. До 2021 года факт использовался как хак для aspect-ratio; сейчас остался, но не нужен — `aspect-ratio` решает задачу нативно.

**Margin: 0 auto работает только для блочных элементов с заданной width.** Inline-элементы (`<span>`, нестилизованный `<a>`) ауто-margin игнорируют — нужно `display: block` или `inline-block` плюс явная `width` / `max-width`. Современная альтернатива — `display: flex; justify-content: center` на родителе.

**Negative margin — инструмент, не баг.** `margin-top: -1px` сшивает border двух соседних карточек. Применение валидно: edge-to-edge изображения, наложение элементов, выход за пределы контейнера. Оборотная сторона — отрицательный margin часто скрывает неправильно настроенный родитель; перед `margin: -16px` стоит проверить, не лишний ли там padding. Eric Meyer и Estelle Weyl в 4-м издании *CSS: The Definitive Guide* (O'Reilly, 2017) разбирают весь этот класс edge-кейсов на 80 страницах главы о box model'е — фундаментальный референс по теме.

<SectionBreak id="07" label="СИНТЕЗ" />

Box model — арифметика одного элемента: что считается, как складывается, по каким осям меряется. Знание этой арифметики недостаточно для современного layout'а, но является его основой: Flexbox распределяет пространство между box-model-коробками; Grid размещает их в tracks; container queries реагируют на размер коробки контейнера. Каждая последующая модель работает поверх box model'а — не вместо него.

Три практических правила:

- **`box-sizing: border-box` глобально** — единственная корректная начальная установка для любого нового проекта в 2025 году.
- **Logical properties по умолчанию** — `padding-block`, `margin-inline-end`, `border-inline-start`. Физические свойства остаются в legacy и в случаях, где направление письма гарантированно фиксировано.
- **Vertical rhythm через `gap`, не margin** — внутри Flexbox/Grid контейнеров. Margin схлопывается, gap — нет; gap не зависит от количества и порядка детей; gap не нуждается в `:first-child`/`:last-child`-сбросах.

<MarginNote>
Rachel Andrew, *The New CSS Layout*, A Book Apart, 2017 — книга о переходе от float-вёрстки к Flexbox и Grid. Тезис, релевантный этому уроку: box model никуда не делся, но способ распределения коробок изменился радикально, и старые техники (clearfix, negative margin, percentage-tricks) сменились декларативными механизмами.
</MarginNote>

Следующая тема трека — `03-flexbox`. Если box model описывает одну коробку, Flexbox описывает распределение пространства между несколькими коробками вдоль одной оси: main axis, cross axis, `justify-content`, `align-items`, `flex-grow`, `flex-shrink`, `flex-basis`. Box-sizing, logical properties и поведение `width`/`height` остаются — Flexbox работает на этой основе, и понимание box model'а даёт читать flex-правила без сюрпризов. Дальше — Grid (`04-grid`), где двумерное распределение делает то же самое одновременно по обеим осям, и container queries (`05-container-queries`), где коробка реагирует на размер собственного родителя, а не viewport'а.
